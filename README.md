# 2048

网页版 2048 游戏，使用 React 19 + TypeScript + Vite 开发。

## 快速开始

```bash
npm install     # 安装依赖
npm run dev     # 启动开发服务器 → http://localhost:5173
```

## 可用命令

| 命令 | 说明 |
| --- | --- |
| `npm run dev` | 启动开发服务器（热更新，同时监听局域网） |
| `npm run build` | 类型检查 + 生产构建，输出到 `dist/` |
| `npm run build:pages` | 构建到 `/2048/` 子路径，供 GitHub Pages 部署 |
| `npm run preview` | 本地预览生产构建产物 |
| `npm test` | 监听模式运行测试 |
| `npm run test:run` | 单次运行全部测试 |
| `npm run typecheck` | 仅做类型检查 |

## 装到手机上

游戏是一个 PWA，可以「添加到主屏幕」当独立 App 使用，并支持离线运行。

**方式一：部署到 GitHub Pages（推荐）**

仓库已带 `.github/workflows/deploy.yml`，推送到 `master` 即自动构建并发布。首次需要在仓库的 Settings → Pages 里把 Source 设为 **GitHub Actions**（或执行 `gh api -X POST repos/<用户名>/2048/pages -f build_type=workflow`）。

发布后用 iPhone 的 **Safari** 打开 `https://<用户名>.github.io/2048/`，点底部分享按钮 → 「添加到主屏幕」。

**方式二：局域网直连（临时试玩）**

`npm run dev` 已监听全部网卡，手机连同一 WiFi 后访问终端里显示的 `Network` 地址即可。这种方式需要电脑一直开着服务。

注意「添加到主屏幕」在 iOS 上**只有 Safari 支持**，Chrome 没有这个选项。

### 离线运行

`public/sw.js` 是一个 Service Worker：首次打开时预缓存全部资源，之后断网也能玩。导航请求走「网络优先、失败回退缓存」，保证有网时能拿到新版本；其余资源走缓存优先。

发布新版本时需要同步递增 `sw.js` 里的 `CACHE_VERSION`，激活时会自动清掉旧缓存。Service Worker 只在生产构建中注册——开发环境下它会缓存旧资源、干扰热更新。

## 玩法

用方向键或滑动屏幕移动所有方块，两个相同数字相撞会合并成它们的和。每次移动后棋盘会随机出现一个新方块（90% 是 2，10% 是 4）。凑出 **2048** 即获胜，之后可以选择继续挑战更高分。棋盘填满且无法再合并时游戏结束。

支持 **4×4** 与 **5×5** 两种棋盘，工具栏可随时切换。两种尺寸的进度与最高分**各自独立保存**，切回去能接着玩之前那局。5×5 格子更多、回合更长，但胜利目标仍是 2048。

### 让每一步更有分量

- **连锁与连击加成。** 一次移动合并越多对，倍率越高（2 对 ×1.5、3 对 ×2.0、4 对 ×2.5）；连续多步都有合并会再叠一层连击加成，每步 +10%、封顶 +50%。因此「憋一手大合并」比零散合并更值。得分为基础分乘倍率后取整，所以不再总是 4 的倍数。
- **下一个方块预告。** 分数旁显示下一个将要出现的方块是 2 还是 4，可以提前规划落点。
- **撤销要花分。** 撤销一步扣 **500 分**，分数不足时按钮禁用（`Z` 键同样无效）。撤销不会降低最高分。
- **危险预警。** 空格只剩 2 格及以内时，棋盘边框会泛红呼吸并伴随低频心跳声，提醒你快没地方了。
- **局后复盘。** 游戏结束时展示这一局的最大方块、移动步数、合并次数、最长连击、撤销次数，并在超过历史最高分时标出「新纪录」。
- **合并爽感。** 每次合并都有高光、向外炸开的火花与冲击波、方块处飘出的 `+N`，并按连锁数与合成数字给棋盘一记轻重不等的震动；音效也带上了打击感。
- **连击喇叭。** 连续合并达到 2 连及以上时，屏幕右上角弹出「连击 ×N」，随连击升级文案与配色（好棒→厉害→无敌…，封顶变彩虹），断连后停留一会儿再淡出。
- **里程碑庆祝。** 本局最大方块首次达到 128 / 256 / 512 / 1024 / 2048 时，弹出大横幅 + 彩纸 + 凯旋音。

### 操作方式

| 操作 | 按键 |
| --- | --- |
| 移动 | 方向键 / `WASD` / `HJKL` |
| 撤销 | `Z` 或「撤销」按钮（每步扣 500 分，最多回退 20 步） |
| 静音 | `M` 或 🔊 按钮 |
| 切换尺寸 | 工具栏的 4×4 / 5×5 |
| 重开 | 「新游戏」按钮 |
| 移动端 | 在棋盘上滑动 |

对局进度、最高分、静音偏好与最后使用的尺寸都会自动保存在浏览器 `localStorage`，关闭页面后仍可继续。

## 音效

所有音效用 Web Audio 实时合成，不加载任何音频文件（零体积、无版权问题）。风格偏克制轻柔：音量压低、衰减快，长时间游戏不吵。

合并音的音高随合成的数字升高，走五声音阶以保证任意组合都不刺耳：

| 数字 | 4 | 16 | 64 | 256 | 1024 | 2048 |
| --- | --- | --- | --- | --- | --- | --- |
| 音高 | C4 | E4 | A4 | D5 | G5 | A5 |

此外滑动、撤销、新游戏、胜利、失败各有对应音效；连锁合并会播一串上行琶音（对数越多爬得越高），进入危险区是两声低频心跳，破纪录是短促的上行三音。首次交互后才会创建 `AudioContext`（遵循浏览器自动播放策略）；环境不支持 Web Audio 时静默降级为无声，不影响游戏。

## 实现说明

**游戏逻辑与渲染分离。** `engine.ts` 是不依赖 React 的纯函数，输入状态输出新状态，随机数发生器通过参数注入，因此测试可以完全复现。所有规则细节（同一方块一次移动内不能二次合并、合并优先级从移动方向的墙壁侧开始）都有对应测试覆盖。

**动画依靠稳定的方块 id。** 每个方块有一个不变的 `id` 作为 React key，位置通过 CSS 变量 `--row` / `--col` 转成 `transform: translate(...)`。位置变化时由 CSS transition 产生滑动效果，而不是重新创建节点。

**合并的视觉处理。** 两块相撞时，被撞的那块保留 id 并翻倍（播放弹出动画），撞过去的那块滑到同一格后标记为「残影」并淡出，在下一回合被清除。这样两个方块都有真实的位移轨迹，看起来就是滑过去再合并。

**方块按 id 排序渲染。** 保证 DOM 顺序稳定，避免 React 重排节点时打断正在进行的 CSS transition；层叠关系交给 `z-index` 控制。

**reducer 保持纯函数。** 随机数在 reducer 外取好经 action 传入，音效也不在 reducer 内播放——reducer 只在 state 里记录「该播什么音」的描述符，由 effect 消费。这样 StrictMode 下 reducer 被重复执行时结果一致，也不会重复发声。切换尺寸同理：存档在 dispatch 之前读好，作为 action 的载荷传入。

**连击是对局数据，统计是会话数据。** 连击计数 `streak` 放在 `Core` 里，因此会随撤销一起回退——撤销掉一次合并，连击也该退回去。而复盘用的累计统计（步数、合并数、最长连击、撤销次数）放在 `GameState`，**不随撤销回退**：它们记录玩家实际做过什么。破纪录判定拿「本局开局时的最高分」当基准，而不是实时抬升的 `best`，否则两者永远相等。危险与破纪录都用 ref 边沿检测触发音效（与胜负音同理），而不是挤进 reducer 的单个音效槽——一次移动可能同时合并、进危险、破纪录，挤在一起会丢事件。

**棋盘尺寸是对局数据而非全局配置。** `size` 存在 `Core` 里，随存档一起持久化，因此加载时能校验「这份 5×5 存档别被当成 4×4 用」。两种尺寸的存档键分开（`state-v2-4x4` / `state-v2-5x5`），撤销栈也各自独立——跨尺寸撤销会产出坐标与尺寸不符的状态。

**切换尺寸时会重建方块节点。** 新对局的方块 id 从 1 重新开始，若沿用纯 id 作为 React key，React 会复用上一个尺寸的 DOM 节点，而节点上残留的 `transform` 是按旧格子尺寸算出的，方块会停在错位的位置。给 `.tiles` 容器加上带尺寸的 key 即可迫使 React 重建。

**字号随尺寸缩放。** `.tile-inner` 的字号用 `cqw`，而容器查询单位相对的是整个棋盘、不是单个格子。5×5 的格子比 4×4 小 23%，字号却不会自动跟随，于是大数字会发挤。`.board` 上的 `--font-scale: calc(4 / var(--size))` 让字号与格子等比缩小，两种尺寸下文字占格子的比例基本一致。

## 测试

```bash
npm run test:run
```

覆盖四个层面：`engine.test.ts` 验证两种尺寸的游戏规则与不变量（含随机对局的模糊测试，检查坐标不越界、无重叠方块、分数自洽、数值均为 2 的幂；5×5 另有奇数宽度下的合并用例），并单独测连锁倍率的边界（0 合并/0 连击不产生小于 1 的倍率）与连击的递增、断裂、封顶；`storage.test.ts` 锁定存档按尺寸隔离、v1 旧存档迁移、缺 `next`/`streak` 的旧存档补默认值、以及尺寸不符 / 坐标越界 / 数值非 2 的幂时的拒绝行为；`sfx.test.ts` 用假的 `AudioContext` 验证音效确实创建了振荡器、音高单调递增、包络有淡入淡出、静音真的归零，含连锁/危险/破纪录三个新音效；`App.test.tsx` 在 jsdom 中渲染真实组件，验证键盘操作、触摸滑动、撤销扣分与买不起时禁用、预告值与落子一致、连锁计分与震动、危险标记、局后复盘、尺寸切换往返与持久化。

jsdom 没有布局引擎，测不出像素对齐与字号观感，所以这两项另外用无头 Chrome 实测：两种尺寸在 320–560px 各视口下的方块与背景格偏移均为 0，5×5 下 5 位数字无溢出。
